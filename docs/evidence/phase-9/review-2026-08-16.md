# Phase 9 review addendum — 2026-08-16

**Result:** accepted by Marc on 2026-08-16 (America/New_York)
**Acceptance lane:** deterministic local fixtures only

## Scope and inventory

Phase 9 is supposed to generate materially different typed candidates, predict
observable consequences, simulate deterministic failure modes, persist a
prediction ledger, reject or modify unsafe candidates before Guardian, and
keep digital-twin and bounded Codex experiments from creating authority or
live effects.

The implementation is isolated under `src/openjarvis/imagination/`:

- `models.py` defines the JSON-round-trippable candidate, action, prediction,
  simulation, critic, score, observation, calibration, and decision contracts.
- `simulators.py` provides symbolic, event-replay, service-dry-run, and
  Home Assistant digital-twin layers.
- `service.py` performs the deterministic departure deliberation, safe
  modification, scoring, replay calibration, and non-authorizing Guardian
  handoff.
- `store.py` provides additive `phase9_*` SQLite tables, idempotent writes,
  immutable audit events, backup, restart recovery, and phase-only rollback.
- `fixtures.py` provides the seeded departure fixture and bounded Codex
  experiment double.

The evidence README and JARVIS assessment were updated with the review
results. Acceptance records were not changed.

## Behavioral fixes made during review

- Symbolic simulation now rejects dependency cycles.
- Simulation runs now store actual deterministic prediction IDs rather than
  expected-observation IDs in `prediction_ids`.
- Replay recording requires a non-empty source ID and `replay` evidence scope,
  and strict comparison avoids treating `True` and `1` as the same value.
- Duplicate replay delivery returns the existing calibration without adding
  another audit event.
- A bounded Codex experiment refuses an existing experiment workspace instead
  of deleting it.
- Contract validation now rejects duplicate action/observation IDs,
  unlinked typed actions, structurally invalid decisions, extra/missing score
  dimensions, and invalid observation/calibration outcomes.

## Safe cleanup

The unused private `SimulationFinding` helper was removed after searching all
repository references. Its module was not registered dynamically, and it was
not exported by the package entry point. Unrelated phase code and ambiguous
public compatibility paths were left untouched.

## Acceptance matrix

- **Happy path:** pass — three substantive candidates are generated; one is
  rejected, one is safely modified, and the consent-preserving candidate is
  selected.
- **Denial/boundary behavior:** pass — seeded cover contradiction, household
  presence, remote-likely calendar evidence, and traffic outage prevent the
  unsafe candidate; only valid candidates reach the handoff; no authorization
  is created.
- **Stale/missing/contradictory/untrusted evidence:** pass for the frozen
  local lane — unknown attendance remains `unknown`, cover feedback is
  contradictory, and replay cannot be labeled `real_observation`; live-source
  freshness and trust policy are deferred.
- **Restart/durability:** pass — records survive SQLite close/reopen and an
  interrupted running simulation becomes failed with unknown real-world
  outcome.
- **Duplicate/idempotency:** pass — duplicate stable ledger writes and replay
  delivery do not create duplicate records or audit events; an existing
  bounded experiment workspace is preserved.
- **Failure/recovery:** pass — seeded digital-twin failure, strict traffic
  failure, bounded Codex failure, and interrupted simulation recovery remain
  simulation-scoped.
- **Timeout/partial failure:** not applicable to the frozen local lane; there
  is no live connector timeout path. Interrupted simulation recovery is the
  applicable local recovery invariant.
- **Rollback/migration:** pass — SQLite backup, migration, phase-9-only
  rollback, re-migration, and preservation of an unrelated table are covered.
- **Side-effect safety:** pass — no network, live Home Assistant, channel,
  calendar, traffic, deployment, or Codex app-server path is used; simulations
  cannot set `real_effect` or `authority_created`.
- **Prior-phase regression:** pass — complete acceptance and targeted Phase 3
  and Phase 7 regression suites are green.

## Known limitations

Implementation limitations remaining in scope are none for the frozen
deterministic acceptance scenario. Deferred live validation remains separate:
the adapter does not connect to live services or the Codex app-server, the
server/UI has no Phase 9 ledger view, and scoring weights, fallback policy,
notification wording, and any future live action types require Marc review.
There is no held-out personal replay measurement in this phase.

Cleanup limitations are also separate: broad cleanup outside the Phase 9
package was not attempted because the working tree contains extensive
unrelated changes. Potential public or dynamically loaded compatibility paths
were retained when removal was not provably safe.

## Acceptance decision

Marc explicitly accepted Phase 9 on 2026-08-16 (America/New_York). Phase 10
was not started. Deferred follow-up is live service and Codex adapters, Phase 9
ledger views, held-out personal replay measurement, and manual review of
scoring weights, fallback policy, notification wording, and future live action
types.
