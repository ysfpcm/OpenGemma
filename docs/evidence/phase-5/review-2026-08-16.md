## Inventory

- Promised deliverable: an additive, opt-in living-world model with typed
  observations, provenance, contradictory evidence, materialized beliefs,
  historical reconstruction, layered memory, and a review-first local history
  importer.
- Implementation: `src/openjarvis/world_model/`, the read-only inspection and
  typed-observation routes in `src/openjarvis/server/world_routes.py`, and the
  server wiring in `src/openjarvis/server/app.py`.
- Dependencies: Phase 4 durable events and existing context/memory/RAG/session/
  trace stores are projected through explicit adapters; no Guardian, executor,
  connector, or live external service is called by Phase 5.
- Frozen scenario: the contradictory priority fixture now passes with source
  deletion, restart, duplicate delivery, malformed-input, failure-retry,
  migration, and opt-in boundary coverage.

## Changes made during this review

- Source identity is preserved across projections; deleted source IDs cannot be
  reused by observations, history, memory, goals, commitments, or predictions.
- Duplicate history delivery preserves review status and returns the persisted
  candidate state instead of resetting accepted candidates to pending.
- Deleting an active correction source now recomputes the prior belief instead
  of leaving it permanently unavailable.
- Expired memory is excluded from active retrieval.
- Review acceptance is recorded only after the observation and memory writes
  succeed, leaving failed reviews pending and retryable.
- The history importer drops candidates from prompt-injection-looking text,
  while retaining the source only as untrusted text.
- The observation API validates enums, timestamps, identifiers, and confidence
  before entering the handler, returning 422 instead of a server error for
  malformed input.
- Added deterministic tests for duplicate delivery, deletion/reuse boundaries,
  review retry, memory expiry, schema migration, opt-in configuration, API
  validation, and API duplicate delivery.
