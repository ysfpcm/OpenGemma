# Phase 1 JARVIS Experience assessment

## Presence

Observable evidence: the Operations panel presents one Ophanim mission narrative—objective, current phase, plain-language progress, and verification—while Codex remains an identified subsystem. No raw protocol method is used as a human-facing milestone when a meaningful summary is available.

## Continuity

Observable evidence: mission, thread, turn, event, and milestone relationships persisted through forced App Server termination. A fresh supervisor found the same mission and accurately retained the interrupted turn classification without ledger corruption.

## Initiative

Observable evidence: Ophanim surfaced material plan, command, tool, file/diff, message, error, and completion milestones from observed events. An identical seeded plan update produced one event and one milestone, not a repeated update.

## Competence

Observable evidence: every public milestone stores the fingerprint of its underlying normalized event. Replay covered each required event class, and the live test retained 100% milestone-to-event traceability. Installed Codex v0.147.0 schema and handshake compatibility were also verified.

## Trust

Observable evidence: all missions force read-only sandboxing, no tool network, and no approvals; workspace paths outside configured roots are refused; incoming approval requests are denied; reasoning content is suppressed; seeded secrets are redacted; and the live test caused no Git workspace change.

## Regressions and deliberately unchanged dimensions

No Phase 0 truthful-lifecycle regression was found in 117 selected backend tests. The existing optional-Rust memory-route baseline failures remain unrelated and unchanged. Voice, visual personality, personal-context initiative, and human mission-control capabilities were deliberately unchanged because Phase 1 is an observer only.
